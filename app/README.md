# JLPT Study for Android

An offline Android app built from the same study core as the CLI: the FSRS
scheduler, the quiz logic and the word bank in `../src` and `../data`. The UI is
a web page (Vite + TypeScript) running inside a Capacitor WebView. The database
is SQLite compiled to WebAssembly (sql.js), stored as `study.db` in the app's
private storage. Speech comes from the phone's own text-to-speech engine. The
app makes no network requests and uses no LLM.

## Install the APK from CI

Every push builds a debug APK in GitHub Actions (`.github/workflows/android.yml`).

1. Open the repository on GitHub and go to **Actions → Android**. Pick the
   latest green run.
2. Under **Artifacts**, download **jlpt-debug-apk**. GitHub serves it as a zip,
   so unzip it to get `app-debug.apk`.
3. Copy the APK to the phone, or download it there directly, and open it.
   Android will ask you to let that app (Files, Chrome, ...) **install unknown
   apps**. Allow it for that one app. The setting is under Settings → Apps →
   Special app access → Install unknown apps.
4. Open **JLPT Study**.

Every build is signed with the same committed debug key
(`android/app/debug.keystore`), so a newer APK installs over an older one and
keeps your review history. If you ever installed a build signed with a
different key, you have to uninstall it first. **Uninstalling deletes
`study.db`**, so export a backup from Settings before you do.

### Japanese voice

Listening cards need a Japanese text-to-speech voice. Most phones have Google's
speech engine. If yours has no Japanese voice data, install it under Settings →
System → Languages → Text-to-speech output → Google → Install voice data →
Japanese. The app's Settings screen links there. Without a voice the app shows
the reading instead, and it doesn't grade that card, so a card you could not
hear never counts against you. The CLI does the same.

## Build locally

You need Node 22 for everything below. A phone build also needs JDK 21 and the
Android SDK, which Android Studio installs.

```sh
cd app
npm ci
npm run dev        # web version at http://localhost:5173, hot reload
```

The web version runs the same code. It stores the database in the browser's
IndexedDB rather than in a file, and speaks through `speechSynthesis` if the
browser has a Japanese voice. Use it for UI work. Use a phone for anything that
depends on the device: TTS voices, saving when the app is paused, file export.

### On a phone over USB

1. On the phone, enable Developer options: tap Settings → About phone → Build
   number seven times. Then turn on **USB debugging** and plug the phone in.
2. Build the web app, copy it into the Android project, and run it on the phone:

   ```sh
   npm run build
   npx cap sync android     # copies dist/ and registers the native plugins
   npx cap run android      # pick the phone from the list
   ```

   `npx cap open android` opens the project in Android Studio instead.

### APK from the command line

```sh
npm run build && npx cap sync android
cd android && ./gradlew assembleDebug
# → android/app/build/outputs/apk/debug/app-debug.apk
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Run `npx cap sync android` after every web build. The Android project only has
the copy of `dist/` made by the last sync. The same command regenerates the
gitignored plugin list (`capacitor.plugins.json`), and that list is how the
text-to-speech, App and Filesystem plugins get registered.

## What's where

| Path | What it is |
| --- | --- |
| `src/` | App UI and the platform layer (sql.js database, storage, TTS) |
| `../src/` | Shared study core, also used by the CLI. Don't fork it here |
| `capacitor.config.json` | App id `io.github.yachi.jlpt`, name, `webDir: dist` |
| `android/` | Generated by `npx cap add android`, then edited: launcher icon and splash (vector drawables), fixed debug signing |
| `test/` | Checks on the built `dist/` (`npm test`) |

The config is JSON rather than `capacitor.config.ts` for a reason. To load a
`.ts` config, the Capacitor CLI calls the TypeScript compiler's JavaScript API.
The app pins TypeScript 7, the native compiler, which doesn't expose that API,
so the CLI fails with `Cannot read properties of undefined (reading 'CommonJS')`.

## Data and backups

`study.db` lives in the app's private files directory. It is an ordinary
SQLite file with the same schema as the CLI's `data/study.db`. A backup you
export from the app (Settings, Export: opens the Android share sheet, so you can save it to Files or Drive) opens with the desktop CLI, and the reverse works too.
Android's Auto Backup (`allowBackup="true"`) also includes it in the phone's
Google backup.
